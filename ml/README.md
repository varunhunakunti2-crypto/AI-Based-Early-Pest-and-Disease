# ML scaffold — reproducible pipeline, no governed model

> **Status: MACHINERY ONLY for the governed pipeline.** This folder proves the
> training/evaluation/promotion plumbing is reproducible. It ships **no approved
> trained model, no real dataset and no approved operating point**, and it makes
> no performance claim. The only data in the governed pipeline are deterministic
> synthetic feature vectors, labelled `is_demo`/`synthetic` everywhere.

This is the Gate 3 training-pipeline scaffold. It complements the serving-side
machinery in `backend/app/modules/assessments/` (quality gate, abstention decision,
calibration, OOD, registry, inference, evaluation). Gate 3 is **not** closed.

## Pretrained third-party detectors (demo only)

Separately from the governed pipeline, this folder contains two wrappers around
pretrained YOLO detectors hosted on Hugging Face:

| Key | Package | Architecture | Classes | Weights |
|---|---|---|---|---|
| `pest` | `agroai_pest_detection/` | YOLO11s (IP102) | 102 | `Yashwanth1508/AgroAI-pest-detection` — `best.pt` (38 MB) |
| `plant` | `plant_diseasedetection/` | YOLOv11x | 116 | `Ananthakrishnanmzen/PlantDiseaseDetection` — `PlantDiseaseDetection.pt` (457 MB) |

They are **not** the governed `pest_ml` pipeline, their weights are not committed,
and they are **demo-only**:

- the class lists do not match the open D1a allowlist, and no mapping exists;
- no calibration or operating point is approved;
- `ultralytics` is **AGPL-3.0** (the model cards say MIT, but that covers the
  weights, not the runtime);
- the models are used outside their validated domain.

Every output is labelled `is_demo: true` and every detection is marked
`unverified_model_label`. Never present this as a diagnosis.

Run the detectors directly:

```bash
# from ml/ — demo-labelled text or JSON
..\backend\.venv\Scripts\python run_pretrained.py --model pest  --image leaf.jpg
..\backend\.venv\Scripts\python run_pretrained.py --model plant --image leaf.jpg --json
..\backend\.venv\Scripts\python run_pretrained.py --model both  --download-only
```

To serve them to the app, use the isolated HTTP service in `serve/` — it keeps
the AGPL runtime out of the backend process. See `serve/README.md`.

| Piece | Where |
|---|---|
| Demo-labelled CLI | `run_pretrained.py` |
| Isolated inference service (`/health`, `/v1/detect`) | `serve/app.py` |
| Regression tests with a fake detector (no torch) | `tests/test_serve.py` |
| Backend HTTP client engine (`APP_CHAT_ENGINE=pretrained`) | `../backend/app/modules/conversations/pretrained_engine.py` |

## What does **not** exist

- No licensed field dataset, data dictionary for real data, or acquisition record.
- No image feature extractor or image model; fixtures start at feature vectors.
- No approved crop/target taxonomy (D1/D2 open), calibration artefact or numeric
  operating point (D8 open).
- No subgroup analysis, field evaluation, model card for a real model, or serving approval.

## Pipeline stages

1. **Manifest** — validates fixture kind, licence, permissions, provenance,
   feature contract, taxonomy and the SHA-256 of the data file. Field datasets
   without documented consent/ethics/owner metadata fail closed; synthetic
   fixtures must be labelled demo.
2. **Splits** — groups by `group_id` (plant/farm/session), stratifies by class and
   seeds assignment. A group appears in exactly one split; a class with fewer
   groups than splits is refused. Splits carry a fingerprint.
3. **Train** — nearest-centroid fixture baseline over supplied feature vectors.
   The artefact is canonical JSON with a SHA-256 checksum; no timestamp is
   invented when a deterministic one is supplied.
4. **Evaluate** — reuses `app.modules.assessments.evaluation` for macro F1,
   per-class precision/recall, confusion matrix and top-k. Calibration diagnostics
   stay `null` until an approved calibration artefact exists.
5. **Promote** — synthetic data may reach `evaluated` **only**. `approved`
   requires non-demo validation/field-test provenance, an approved calibration
   version and an explicit human approval timestamp. The resulting registry entry
   is validated by the backend's `ModelRegistry` schema.

## Plugging in a real dataset (not done)

A real pipeline needs, at minimum:

1. Decisions D1 (crop/targets), D2 (taxonomy) and D8 (recall floors/operating
   point) recorded in `../final/docs-context/progress-tracker.md`.
2. A dataset manifest with `fixture_kind: "field_dataset"`, `is_demo: false`, a
   real licence and `permissions.consent_ref` / `ethics_ref` / `data_owner`
   (plus `privacy_review_ref` if personal data is involved).
3. A documented, versioned feature extractor that replaces the synthetic feature
   contract but preserves training/serving parity.
4. A dedicated calibration split and an approved calibration artefact; then a
   frozen test-set evaluation and subgroup analysis.
5. Human approval before `status: "approved"` and serving.

The label map in `contract/label_map.synthetic.json` is **not** a production
taxonomy. Do not use it in the app.

## Honesty rules enforced here

- Synthetic data cannot be approved for serving.
- Metrics always carry provenance (`synthetic_fixture` for this scaffold).
- Calibration stays unavailable until explicitly fitted and approved.
- A group cannot be split across train/val/test.
- The model card states its own limitations and bans field use.
